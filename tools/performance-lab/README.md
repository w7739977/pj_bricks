# 游戏性能测试入口

Node.js20+，无需安装第三方依赖。在项目根目录运行 `npm run test:perf`，打开 http://127.0.0.1:3014/ 。服务器仅监听回环地址。它读取当前仓库的 dist，并在响应中注入测试面板；不会修改游戏文件。报告写入忽略提交的 `test-artifacts/performance/`。

可用环境变量 GAME_ROOT 指定另一个包含dist的项目根目录，PORT改端口，LAB_OUTPUT改报告目录。`PROFILE=1 npm run test:perf` 可包装同步关键函数，记录函数调用耗时；计时有少量额外开销，对照组应保持相同设置。

## 持续拖动与回退

1. 第1关消除第一行右上角相邻的生菜，腾出两个空位。
2. 点击“启用持续拖动回放”，按住第一行最左侧棋子5秒。真实按下启动，逐帧合成移动执行连续拖动，末端保留位移后松手，以覆盖长链回退。
3. 松手后等待至少1.1秒再点“保存报告”。原始帧样本、移动事件、前后棋盘和错误列表都会保留。
4. 运行 `node tools/performance-lab/analyze.mjs test-artifacts/performance/<文件名>.json`。退出码0表示这些有效样本未观察到阈值内卡顿，1表示观察到卡顿，2表示样本不足或缺少结果。

手工拖动直接记录真实输入，不必启用回放。接管工具若在松手时移回鼠标，可在URL添加 `?tool=1`，排除其原生回位事件；这会过滤真实鼠标移动，手工操作时不要启用。合成与原生移动分别记录，不把回放当作手机真人输入延迟测试。

同一棋盘可切换独立滤镜/阴影/空闲动画实验。**当前生产CSS已关闭滤镜与空闲动画，实验“原版”只表示没有额外覆盖，不会恢复已移除的效果。** 比较修正前后请使用各自Git版本启动服务器。

## 直接线上诊断

`probe.js` 也可由开发者审阅后，通过浏览器开发者工具临时注入线上当前页。若浏览器显示防误粘贴提示，须由操作者本人审阅并完成浏览器要求的确认，不要关闭安全保护来自动执行。用 `void (()=>{ /* probe.js 的完整内容 */ })();` 将脚本包在函数作用域中，防止全局名称冲突。

在非本机域名上，“保存报告”只会生成一个只读的“性能报告JSON”文本框，不向线上服务器上传数据。复制其内容保存为JSON后用analyze.mjs分析；刷新页面会移除全部临时探针和实验样式。

## 指标边界

- 有效拖动至少30帧、10个移动事件，并须观察到拖动层；取消或后台样本不验收。
- 同时观察拖动阶段和松手后1秒。拖动慢帧超过5%、观察到长任务或松手最大rAF间隔超过50ms会标记卡顿。这是筛查阈值，不是产品流畅度标准。
- rAF不等于GPU呈现FPS，输入至下一rAF不等于端到端输入延迟。PerformanceObserver不支持的指标由supports字段说明，空列表不能当作通过。
- iPhone Chrome与桌面Chrome不能互相替代验收；本轮iPhone没有连接远程真机调试。

结果与原因见 `docs/performance/2026-11-08.md`。
