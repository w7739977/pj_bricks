# 操作手感与果园界面接续记录

## 第一批：连续点按与锁轴采样

- 状态：代码完成，Chromium 手机视口已验收，iPhone Chrome 真机待验收。
- 基线为 `402cd37`。本节点同时收录此前已试玩的果园 Demo、头栏和本地字体。
- 消除动效期间最多缓存一次完整点按。棋盘恢复可交互后，只有该棋子仍在原位且有合法目标才执行。滑动、取消、离开页面和切关均清理对应输入。
- 测试面板按游戏实际锁轴记录 `dragAxis` 和按下到锁轴的 `dragAxisMs`。7×7 px 斜移记录为点按，15×7 px 移动和仅松手达到阈值均记录为横向拖动。
- 验证：同一开局的两组配对，相隔约 75、150、350ms 均从 140 枚降到 136 枚。取消、滑动和点到已消失棋子时保留 138 枚。配置本机 Chromium 后，`npm test` 128 项通过，`git diff --check` 通过。

## 接续入口

1. 在仓库根目录运行 `LAB_HOST=0.0.0.0 npm run test:perf`。Mac 打开 `http://127.0.0.1:3014/demo`。同一 Wi-Fi 下，iPhone Chrome 打开 Mac 局域网 IP 的 3014 端口和 `/demo`。
2. iPhone 使用同一开局，复测快速两次消除、点按轻微偏移、长链回弹和撞边反向。面板保存 JSON，报告需注明机型和 iOS 版本。
3. 第二批从轻微预跟随原型开始。以当前固定阈值为对照，同机同盘每组每类至少 10 次，检查首次可见移动、误锁轴、拖动 P95 和松手峰值。重点确认误拖是否增加。
4. 后续依次整理果园正式界面和盘内引导，再用真人数据复核第 10 关附近的首次救局与第 15–20 关道具使用。
