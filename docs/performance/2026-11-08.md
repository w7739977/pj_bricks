# WebKit 卡顿修正与线上 Chrome 复测

测试日期：2026-11-08。线上地址：http://119.91.53.223:3013/ 。仓库基线d7819a9的CSS与线上下载文件SHA256一致。

## 修正

棋盘SVG的drop-shadow、约20个棋子的无限空闲动画与棋子容器阴影叠加，在Mac Safari长链松手回退阶段稳定出现234–287ms的rAF空档。关闭图案滤镜与空闲动画、保留棋子容器阴影后，写入实际CSS的副本四次测得23–45ms。

`dist/styles.css`末尾新增两个声明，仅关闭`.cell .veg`与`.drag-layer .veg`的filter和animation。保留棋子阴影、图案、拖动、吸附、消除反馈。视觉取舍是取消轻微呼吸效果和图案外投影。游戏规则与存档代码未改动。

## 直接线上 Chrome

在Mac Chrome156打开实际IP网址，以浏览器开发者工具临时装入探针；没有替换线上服务器文件。原版、临时修正版各4次持续拖动，共2,399帧、2,113个移动事件。

- 原版松手最大rAF间隔：17.7–17.8ms。
- 临时修正版：17.7ms。
- 8次均观察到拖动层，前后棋盘还原，未记录运行异常或长任务。
- 此次页面load约5.21秒，部分静态资源耗时数秒；加载完成后的这组拖动没有新增同源资源请求。因此加载等待与本场景运行时渲染应分别判断。

结果见`remote-chrome-summary-20261108.json`。这说明该桌面Chrome长链场景未复现明显帧间隔尖峰，不表示所有场景或手机都流畅。Event Timing中原生鼠标释放事件有约56ms记录；回放仍不能当作真人输入端到端延迟验收。

## iPhone Chrome 的边界

用户确认手机为iPhone。Chrome的iOS平台使用WebKit封装WKWebView，与Mac桌面Chrome的Blink不能互相替代验收：[Chromium ios/web文档](https://chromium.googlesource.com/chromium/src/+/HEAD/ios/web/)。地区及发行版本可能存在平台特例，未读取用户手机版本。

检查了本机Safari“App和设备检查”：只显示本Mac，没有可用iPhone连接。**未完成iPhone Chrome真机远程测试，也不宣称手机卡顿已全部修复。** Mac Safari验证证明这项CSS修正在WebKit场景有效，是针对手机问题的有根据修正；手机效果仍需实际部署后复测。

## 验证及复现

- 当前仓库116项既有单元测试全部通过。
- 新测试入口server/probe/analyze均通过Node语法检查。

rAF是回调节奏而非实际GPU呈现FPS，不能把短样本或不支持的PerformanceObserver指标当作性能通过。控制回放显式标记合成输入；`?tool=1`过滤接管工具在松手时移回指针造成的额外事件。真实手工拖动不要开启该参数。生产页面不会自动加载这些测试工具。

本提交只更新GitHub仓库，不代表线上IP服务器已完成部署。部署dist更新后应复查线上CSS，再进行iPhone验收。
